# 4. Модели: общие понятия

В пакете два вида моделей. Они работают вместе, но используются и по отдельности.

| Вид | Что делает | Метод | Что возвращает | Каталог в коде |
|---|---|---|---|---|
| **Модель режима потока** (`IFlowModel`) | Определяет режим течения по состоянию потока | `predict(state)` | `FlowPatternResult`: режим и промежуточные величины | `flow_models/` |
| **Корреляция** (`ICorrelation`) | Полный расчёт: режим, истинное содержание жидкости и градиент давления | `calc(state)` | `CorrelationResult` | `models/` |

Корреляция не определяет режим сама: она обращается к **внедрённой модели режима**. По умолчанию у
каждой корреляции есть своя «родная» модель режима, но её можно заменить (подробности — в
[разделе о корреляциях](05-correlations/README.md)).

## Доступные модели

| Корреляции (`list_correlations()`) | Модели режима (`list_flow_models()`) |
|---|---|
| `ansari` | `ansari_fp` |
| `beggs_brill` | `barnea` |
| `hasan_kabir` | `beggs_brill_map` |
| `mukherjee_brill` | `hasan_kabir_fp` |
| | `mukherjee_brill_fp` |
| | `taitel_dukler` |

Модель режима по умолчанию для каждой корреляции:

| Корреляция | Модель режима по умолчанию |
|---|---|
| `beggs_brill` | `beggs_brill_map` |
| `mukherjee_brill` | `mukherjee_brill_fp` |
| `hasan_kabir` | `hasan_kabir_fp` |
| `ansari` | `ansari_fp` |

Модели `barnea` и `taitel_dukler` самостоятельных корреляций не имеют: это механистические модели
режима, которые можно подставить в корреляции, умеющие считать выдаваемые ими режимы.

## Общие интерфейсы

Интерфейсы заданы структурно (`typing.Protocol`), поэтому собственная модель подходит, если
реализует нужные атрибуты:

- у модели режима: имя `name`, настройки `options`, метод `predict(state)`;
- у корреляции: имя `name`, настройки `options`, свойство `flow_model`, метод `calc(state)`.

Конструкторы единообразны: модель режима — `Model(options=None)`; корреляция —
`Correlation(options=None, flow_model=None)`. Все экземпляры после создания не меняют настройки.

## Реестр

Реестр создаёт модели по имени и флагам настроек:

| Функция | Что делает |
|---|---|
| `get_correlation(name, flow_model=None, **flags)` | Создаёт корреляцию. `flow_model` — готовый экземпляр модели режима, имя модели режима (создаётся с настройками по умолчанию) или `None` (модель режима по умолчанию) |
| `get_flow_model(name, **flags)` | Создаёт модель режима |
| `list_correlations()` | Отсортированные имена корреляций |
| `list_flow_models()` | Отсортированные имена моделей режима |
| `describe_correlation(name)` | Словарь «флаг → описание» корреляции |
| `describe_flow_model(name)` | Словарь «флаг → описание» модели режима |

Те же модели можно создавать напрямую по классам (`BeggsBrill`, `BarneaModel`, …) с объектами
настроек (`BeggsBrillOptions`, `BarneaOptions`, …); все они экспортируются из пакета.

## Флаги настроек

Настройки каждой модели — набор булевых флагов (`BaseOptions`):

- значение по умолчанию соответствует оригинальной статье-первоисточнику;
- у каждого флага есть описание: что меняет, когда включать и источник (доступно через
  `describe_*`);
- флаги проверяются строго (см. [раздел о проверке данных](02-validation-and-errors.md));
- полные таблицы флагов всех моделей приведены в [README проекта](../../README.md).

Флаги бывают нескольких типов:

| Тип флага | Назначение | Пример |
|---|---|---|
| Выбор метода | Альтернативный способ расчёта, предложенный авторами или практикой | `revised_map`, `payne_correction`, `porteous_low_pressure` |
| Сверка | Воспроизведение примера из монографии или другого ПО | `include_acceleration=False`, `developing_slug=False`, `ff_over_fsl_unity` |
| Буквальное воспроизведение статьи | Формула «как напечатано» вместо принятого исправления | `eq56_as_published`, `vo_shoham_a_as_published`, `wall_shear_as_published` |
| Выбор модели трения | Гладкая формула или Colebrook | `rough_pipe_friction`, `use_moody_friction` |

## Что возвращают модели

Подробно результаты описаны в разделах [о режимах](06-flow-patterns/README.md) и
[о градиенте давления](07-pressure-gradient.md). Кратко:

- `FlowPatternResult` — поле `pattern` (режим, `FlowPattern`) и словарь `details` с
  промежуточными величинами; имена ключей содержат единицы (например, `h_l_over_d`).
- `CorrelationResult` — режим, истинное содержание жидкости `holdup`, полный градиент давления
  `dpdl_pa_m`, его составляющие (`dpdl_gravity_pa_m`, `dpdl_friction_pa_m`,
  `dpdl_acceleration_pa_m`) и словарь `details`.

## Источники и расхождения

Для каждой корреляции в docstring указан первоисточник (статья, номера уравнений). Если формула в
источнике содержит опечатку или расходится с принятой реализацией, это явно написано в docstring
модуля, а альтернативное поведение (когда оно есть) включается флагом.
