# 2. Проверка данных: pydantic, ошибки и предупреждения

Все входные и выходные структуры пакета — модели `pydantic`, настройки — набор булевых флагов.
Неверные данные отклоняются **до** расчёта, а не приводят к молчаливо неверному результату.

## Три источника проблем

| Источник | Исключение / предупреждение | Когда возникает |
|---|---|---|
| Входные данные и флаги | `pydantic.ValidationError` | Поле вне допустимого диапазона, неверный тип, лишнее или недостающее поле, несогласованные значения |
| Имя модели в реестре | `ValueError` | Имя корреляции или модели режима не зарегистрировано |
| Сам расчёт | `ConvergenceError`, `UnsupportedPatternError` | Решатель не сошёлся; модель режима вернула режим, который корреляция не умеет считать |
| Область применимости | `OutOfRangeWarning` | Расчёт выполнен, но вне области применимости формулы |

## Правила pydantic для `FlowState`

`FlowState` создаётся с настройками `frozen=True`, `extra="forbid"`, `strict=True`,
`allow_inf_nan=False`. Что это означает на практике:

- **Неизменяемость (`frozen`).** После создания поле менять нельзя — попытка присваивания даёт
  `ValidationError`. Чтобы изменить значение, создайте новое состояние.
- **Запрет лишних полей (`extra="forbid"`).** Опечатка в имени поля — ошибка (`extra_forbidden`),
  а не игнорируемый параметр.
- **Строгие типы (`strict`).** Строка вместо числа (`"1.0"`) и булево значение вместо числа
  отклоняются (`float_type`). Целое число для поля типа `float` принимается и преобразуется в
  `float`.
- **Только конечные числа (`allow_inf_nan=False`).** `NaN` и `inf` отклоняются
  (`finite_number`).
- **Обязательные поля.** Пропущенное обязательное поле даёт ошибку `missing`. Необязательные —
  `d_t_m` и `eps_m` (по умолчанию 0).

Диапазоны каждого поля приведены в [разделе о входных данных](03-input-data.md).

## Проверки согласованности

Кроме диапазонов отдельных полей, проверяется согласованность значений. Нарушение даёт
`ValidationError` с типом `value_error` (сообщение на русском):

| Условие | Смысл |
|---|---|
| ρ_L > ρ_g | Жидкость должна быть плотнее газа |
| d_t < d | Наружный диаметр НКТ меньше диаметра внешней трубы |
| ε < d | Шероховатость меньше диаметра |
| v_sl + v_sg > 0 | Хотя бы одна фаза течёт |

Однофазные пределы допустимы: `v_sl = 0` (чистый газ) и `v_sg = 0` (чистая жидкость) — это не
ошибка, модели режима возвращают режимы `SINGLE_PHASE_GAS` и `SINGLE_PHASE_LIQUID`.

## Проверка флагов настроек

Флаги задаются классом `<Имя>Options` (наследник `BaseOptions`) и проверяются так же строго:

- неизвестное имя флага — `ValidationError` (`extra_forbidden`);
- значение не `bool` (в том числе `1` или `"true"`) — `ValidationError` (`bool_type`);
- набор флагов неизменяем после создания.

Сами классы настроек проверяются при объявлении: каждое поле обязано иметь тип `bool` и непустое
описание, иначе при определении класса возникает `TypeError`. Это гарантирует, что описание
каждого флага доступно через `describe_correlation` / `describe_flow_model`.

## Результаты тоже проверяются

- `CorrelationResult.holdup` обязан лежать в диапазоне 0…1.
- Полный градиент `dpdl_pa_m` обязан совпадать с суммой составляющих (гравитационная +
  трение + ускорение) с относительной точностью 1e-10. Нарушение — внутренняя ошибка расчёта,
  которая сообщается `ValidationError` при построении результата.

## Ошибки пакета

### `ConvergenceError`

Итерационный решатель не сошёлся (например, не найден равновесный уровень жидкости в расслоённом
потоке или толщина плёнки в кольцевом режиме). Исключение хранит `params` — словарь параметров
задачи, при которых решение не найдено, и выводит их в сообщении. Для диагностики сохраните эти
параметры; изменение входных данных на малую величину часто снимает проблему.

### `UnsupportedPatternError`

Модуль режима вернул режим, который выбранная корреляция не умеет обрабатывать. Исключение хранит
`pattern` (режим) и `source` (имя корреляции). Причина — несовместимая пара «корреляция + модель
режима» (подробности в [описании корреляций](05-correlations/README.md)).
Наследует `ValueError`.

### `ValueError` реестра

Неизвестное имя корреляции или модели режима. В сообщении перечислены все доступные имена.

## Предупреждение `OutOfRangeWarning`

Наследует `UserWarning` и выдаётся через `warnings.warn`; числовые величины, связанные с
предупреждением, лежат в атрибуте `context` (словарь «имя → значение»): расчёт **выполнен**, но результат может
быть недостоверен, потому что формула применена вне области, для которой она получена. Примеры:

- корреляция Hasan–Kabir рассчитана для угла, отличного от 90° (модель создана для вертикального
  подъёма; гравитация считается с sinθ). Текст предупреждения не содержит значения угла — оно в
  атрибуте `context["theta_deg"]`; отключается флагом `warn_non_vertical=False`;
- Re плёнки в кольцевом режиме меньше 3000 — корреляция Steen–Wallis вне области применимости;
- относительная шероховатость ε/d выше 0.05 (граница диаграммы Moody): коэффициент трения
  рассчитан при ε/d = 0.05;
- Hasan–Kabir, модель режима: ρ_L·v_Ls² выше 3300 lbm/(ft·s²) вне пузырькового и кольцевого
  режимов — принят режим CHURN.

С предупреждениями можно работать стандартными средствами модуля `warnings` (фильтры, перехват,
превращение в ошибки). Игнорировать их без анализа не рекомендуется — они указывают на
расчёт вне области применимости.

## Что не проверяется

Библиотека проверяет формальную корректность и согласованность данных, но не физическую
правдоподобность (например, что плотность газа соответствует давлению и температуре). Подготовка
свойств флюидов — задача вызывающего кода.
