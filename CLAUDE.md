#CLAUDE.md - Correlations
## О проекте
 Python - библиотека содержащая корреляции для расчета давления в скважине при движении газожидкостной системы. На данный момент реализованы: ansari, beggs_brill, taitel-dukler, barnea, hasan-khabir, mukherdge-brill. Планируется расширять количество корреляций, приоритеты отдается механрстическим моделям, а не империческим.

## Окружение и команды
Windows, PowerShell, менеджер окружения — uv.

Зависимости: uv add <пакет> (не pip install)
Тесты: uv run pytest -q
Линтер и формат: uv run ruff check --fix . и uv run ruff format .
Типы: uv run pyright
Всё сразу: uv run python check.py
[! warning] Важное правило
Приустановке зависимостей всегда проверяй где находится python интерпретатор: команда Get-Command python
Если выбран глобальный интерпретатор, то необходимо активировать виртуальное окружение командой .venv/Scripts/activate.ps1

## Правила написания кода
Полная типизация, код должен проходить Pyright без ошибок.
Публичный API — в библиотеке;
Валидация с помощью pydantic 
Физические величины — в СИ, единицы указывать в docstring и именах при неоднозначности (например, velocity_m_s).
Для каждой корреляции в docstring указывать первоисточник (статья, уравнение).
В начале пакета корреляции написать docstring со схемой расчет по этой корреляции.
Для каждого метода нужно прописывать в docstring какие параметры он принимает, что выводит и что он делает
Не менять коэффициенты и критерии переходов в корреляциях без ссылки на источник. Если формула в коде расходится с источником — сообщить, а не «исправлять» молча.

## Область работы
Работай только в файлах и модулях, указанных в задаче.
Если для задачи нужно изменить что-то за пределами этой области — сначала спроси.
Не делай попутный рефакторинг несвязанного кода; предложи его отдельным пунктом в отчёте.
Не открывай системные файлы, файлы окружения и т.д., работай только внутри модуля correlations (разрешено работать в pyproject.toml)

## Порядок работы
Для задач больше одного файла — сначала план, жди подтверждения.
После рефакторинга кода и исправления ошибок запускай тесты запускай тесты и ruff.
При добавлении нового кода для расчёта корреляций сначала напиши тесты по источникам и разделу «Тесты и эталонные значения» ТЗ, затем приостанови задачу и запроси подтверждение тестов. Код пиши только после подтверждения.
После выполнения задачи запускай тесты и линтеры
Не помечай тесты как skip/xfail и не ослабляй проверки, чтобы тесты прошли.
